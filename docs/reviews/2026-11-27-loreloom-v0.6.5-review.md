# Loreloom v0.6.5 — Review, Fix List, Competitive Comparison & Roadmap

**Date:** 2026-11-27 · **Scope:** the whole repo at `7aa8f62`, about 12.7k lines of TypeScript.
**Checks run:**
- `tsc --noEmit` is clean.
- `vitest run`: 26 of 26 tests pass, in 11 files.
- There are no renderer or UI tests.
- The worst bugs (wikilink escaping, checklists lost on reload) were reproduced by running the real libraries.

---

## TL;DR

Loreloom has an unusually wide feature set for about two days of history (24 commits). It covers maps, moodboards, a graph, the Bible export, intake sync and theming, and it rests on a sound architecture: Markdown files are the source of truth, and a local SQLite index sits outside the synced folder. That is the right base for a OneDrive or Drive lore vault.

**However, the persistence layer currently damages your lore.**
- **Wikilinks are corrupted on every save.**
- **Checklists, links and tables are lost on edit.**
- **Autosave can write one entry's text into another.**
- **Intake re-syncs overwrite your manual edits.**
- **Sync from another PC is silently overwritten by whatever the open editor holds.**

Fix the P0 list below **before you put more Brimstone or Neon Ash lore into it**. Until then, keep a git repo or zip backup of the workspace folder.

The order that gets you to best-in-class:
1. **Make it trustworthy:** no data loss, conflicts handled, trash and history.
2. **Make it fast at scale:** incremental index, transactions, thumbnails, virtualization.
3. **Close the Notion gaps that matter for lore:** real database properties, sub-pages, callouts and toggles, templates.
4. **Lean into what neither Notion nor Granola can do:** lore-aware AI with canon consistency, spoiler and canon layers, in-world calendars and timelines, game-dev export.

## 1. Corrections & fixes

Severity: **P0** means data loss or corruption, so fix now. **P1** means a serious bug, security issue or scale problem. **P2** is a correctness or UX defect. **P3** is polish.

### P0 — Data loss / corruption

> **Status (2026-11-27):** All 14 P0 items are fixed on branch `claude/loreloom-app-review-e5cda4`, with regression tests in `src/core/__tests__/data-safety.test.ts` and `src/renderer/lib/__tests__/markdown-codec.test.ts`. Footnotes and raw HTML in notes are still not preserved by the editor.

|---|---|---|---|
| 1 | **Every save escapes wikilinks.** Turndown turns `[[Iron Citadel]]` into `\[\[Iron Citadel\]\]` and `_` into `\_`. | 10 | **Unknown frontmatter is deleted on save.** `serializeEntry` writes only known keys, so `aliases`, `cssclasses`, `date` and any custom keys from Obsidian or AI notes disappear. | # | Problem | Where | Fix |

### P2 — Correctness / UX defects (from the UI audit)

- **Slash and `[[` menus.**
  - They render at the bottom of the document, not at the cursor.
  - There is no keyboard navigation, Esc doesn't close them, and the slash menu doesn't filter as you type.
  - Any `/` opens the menu (for example in "and/or").
  - `runSlashCommand` deletes the wrong character if you typed after the `/`.
  - **Fix:** rebuild them on `@tiptap/suggestion` with Tippy or floating-ui.
- **Typing in the title gets overwritten** when a body autosave comes back (`EntryEditor.tsx:189`).
- **The same entry open in both split panes** overwrites itself, last write wins.
- **Map pin and moodboard fields write the file on every keystroke.** Characters get dropped and writes can land out of order (`MapsView.tsx:137, 392, 456`).
- **Tabs and the split pane can point at deleted entries** and render blank. Quick-switching worlds doesn't reset the tabs (`App.tsx:611, 811-829`).
- **Stale closures in App.** `loadWorkspace` and the `paletteCommands` memo capture an old `setActiveView`, so palette "Go to" can land on a tab that doesn't exist. `setActiveTabId` is called inside a `setTabs` updater.
- **Failures are silent.** `.catch(() => {})` is used everywhere. A failed save shows "Saving…" forever, and a missing workspace folder gives no explanation.
- **Custom entity types.**
  - IDs can collide; naming one "Character" duplicates `character`.
  - Field keys can come out empty.
  - Every field is text only, and types can't be edited or deleted.
  - Only *select* and *text* properties have UI. Multi-select, date and number exist in the schema but render as text, and arrays are saved back as one comma-joined string.
- **Collection view settings reset** on every workspace reload.
- **Image paths with spaces or `)`** don't round-trip safely (`EntryEditor.tsx:50, 59`).
- **Dragging a graph node opens the entry.** Wheel `preventDefault` does nothing inside React's passive listeners.
- **Small issues.**
  - Naive plurals such as `classs/`.
  - The split-pane picker lists only the 60 most recent entries.
  - Toast timers are never cleared.
  - Export references a `template` type that doesn't exist.
  - The kanban "Unassigned" column disappears when it is empty.
- **Accessibility.**
  - There are no `role` or `aria-*` attributes.
  - No modal has a focus trap, and only the quick switcher handles Escape.
  - Kanban, graph and maps only work with a mouse.

### P3 — Engineering health

- **Split up `App.tsx`.** It is 884 lines with about 20 `useState` hooks, every IPC handler and two hand-copied view switches. Move to a store (Zustand) plus a query cache (TanStack Query), and give each pane its own `<PaneView>` component.
- **Add tests where the bugs are:**
  - Editor round-trip tests (md → TipTap → md).
  - Tests that fire autosave while switching entries.
  - An intake re-sync test that preserves user edits.
  - A manifest test where a file is missing.
  - A Playwright-Electron smoke test.
- **Expand CI.** Add a lint step (ESLint plus `react-hooks/exhaustive-deps`, which would have flagged several of the stale-closure bugs) and an `electron-builder --dir` packaging check.
- **Bump Electron and enable Renovate.**

### Where each one wins

- **Loreloom already beats both** on:
  - Worldbuilding-specific tools (maps, moodboards, art linking, labelled relationship graph, themes, bible export).
  - Owning your data as plain files.
  - The intake pipeline for AI-generated lore.
- **Notion wins** on editor depth, databases, templates, history and trash, collaboration, AI and mobile.
- **Granola** doesn't really compete as a lore wiki. It is an AI meeting and conversation notepad. What is worth borrowing is the workflow: **you jot rough notes, AI expands them using context, and you can chat with the whole corpus.** For a worldbuilder that maps to brainstorm sessions, voice memos, playtest or table-session recordings, and writers' room calls.

## 3. Roadmap to best-in-class

### Phase 0 — Trust (1–2 weeks). *Nothing else matters until this ships.*
1. P0 items 1–14. Start with the editor round-trip test suite and a markdown-aware TipTap setup.
2. Conflict detection with `.conflict` files and a merge banner, reload the open entry on external change, and a `.trash/` folder with restore.
3. **Version history for free:** keep a rolling snapshot of each entry's last N saves in a local `history/` folder, or use an embedded git repo (isomorphic-git) in the workspace with auto-commits every few minutes. Show a "Page history" diff view. Notion charges for this.
4. Security: limit the updater URL, verify the signature, use `safeStorage`, add a CSP, `sandbox`, navigation guards and bundled fonts. Upgrade Electron.

### Phase 1 — Speed & robustness (2–3 weeks)
- Incremental index plus transactions plus echo suppression. Look up entries by path through the index.
- One file per record for manifests, maps, boards and types.
- Thumbnail cache, virtualized lists and grids, and a graph that runs in a Web Worker or WebGL.
- Split `App.tsx` into stores and a query cache, and add ESLint hooks rules plus Playwright smoke tests.

### Phase 2 — Notion parity where it matters for lore
- **Editor:** links, tables, callouts (with lore styles: *Canon*, *Rumor*, *GM Secret*), toggles (good for spoilers), columns, embeds, block drag handles, a bubble toolbar, H1–6, and a floating slash menu with fuzzy search.
- **Properties:** number, date, checkbox, URL, multi-select chips, **relation (typed)**, **rollup** (for example "Faction → members' count"), formula, and a field-type picker plus editing for custom types.
- **Views:** an editable table with column config, filter and sort builders, saved views per collection, a list view, and a calendar view on the in-world calendar.
- **Sub-pages, entry templates** ("New Character from *Brimstone NPC* template"), favourites, recent pages, and `aliases:`.
- **Rename-aware links:** updating a title offers to rewrite every link to it.

### Phase 3 — Leapfrog: things neither Notion nor Granola does for worldbuilders
1. **Lore-aware AI (Claude) with canon guardrails:**
   - *Ask the World:* RAG over the world with citations to entries.
   - *Continuity checker:* flags contradictions such as "Kael is 34 in *Kael* but born in 3E 212, which makes him 41".
   - *Auto-link suggester:* finds unlinked mentions and offers `[[ ]]`, the way Obsidian does.
   - *Expand stub:* writes a draft from the type template and related entries.
   - Embeddings stay in the local SQLite index (sqlite-vec). AI is opt-in for each world.
   - This replaces the manual prompt-framework export with a proper loop.
2. **Granola-style session capture:** record a brainstorm, voice memo or playtest. Transcribe locally (Whisper.cpp) or through an API. Then merge your rough notes with the transcript into structured lore, and **propose new or updated entries as diffs for you to approve**. It is the intake pipeline, but for speech.
3. **Canon layers and spoilers:**
   - Mark blocks or entries *Canon / Draft / Retconned / Player-Safe*.
   - Have a "player view" export that strips GM secrets.
   - A World Bible that filters by layer.
4. **In-world calendars and timelines:**
   - Custom calendars (months, eras, `3E 212`).
   - Date properties typed to that calendar.
   - A real zoomable timeline with parallel tracks per faction or character, and age calculations.
5. **Cross-world shared canon:** Brimstone and Neon Ash could share a universe or entries such as a "Multiverse" world, linking across worlds with `[[neon-ash:Entry]]`.
6. **Game-dev export:**
   - JSON, CSV or YAML per collection for Godot, Unity or Unreal (dialogue IDs, item tables).
   - An Ink or Yarn stub export for characters.
   - A static wiki site build (Astro), so you can publish to the web with a spoiler filter.
7. **Map upgrades:**
   - Map layers (political, terrain).
   - Region polygons linked to Locations.
   - Distance and travel-time ruler on a set scale.
   - Pins filtered by timeline era, to see the map at a point in time.
8. **Mobile capture companion:** a small PWA or iOS share sheet that drops notes, voice memos and images into the intake folder. The existing pipeline then files them.
